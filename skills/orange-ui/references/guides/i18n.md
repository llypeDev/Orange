# Internacionalização

Os componentes do Orange falam português, inglês e espanhol. Rótulos internos — “Fechar”, “Próxima página”, “Carregando…” — vêm de um dicionário que você escolhe, traduz ou sobrescreve pelo OrangeProvider.

## O locale do provider

Passe `locale` no `OrangeProvider`. O dicionário é escolhido pelo valor exato (`pt-BR`, `en-US`), depois pelo idioma ( `pt`, `en`) e, por fim, cai em `pt-BR`. O provider não muda o `lang` do documento — sincronize-o você mesmo.

`main.tsx`:

```tsx
import { OrangeProvider } from '@orangesys/ui'

const idioma = navigator.language.startsWith('en') ? 'en-US' : 'pt-BR'
document.documentElement.lang = idioma

createRoot(root).render(
  <OrangeProvider locale={idioma}>
    <App />
  </OrangeProvider>,
)
```

## Espanhol

O dicionário `esES` (espanhol da Espanha) tem todas as chaves traduzidas. Ele não vem embutido no provider, para não pesar no bundle de quem não usa: importe-o e passe em `messages`, junto com o `locale`, que cuida de datas, números e ordenação.

`main.tsx`:

```tsx
import { esES, OrangeProvider } from '@orangesys/ui'

document.documentElement.lang = 'es-ES'

createRoot(root).render(
  <OrangeProvider locale="es-ES" messages={esES}>
    <App />
  </OrangeProvider>,
)
```

> **Locale sem dicionário** Com um `locale` que não é português nem inglês e sem `messages`, os textos internos ficam em português. Em desenvolvimento, o provider avisa no console. Para ajustar um texto do espanhol, espalhe o dicionário: `messages={{ ...esES, close: "Cerrar ventana" }}`.

## Mensagens internas ao vivo

Cada componente lê seus textos com `useLocale().t(chave, variáveis)`. Troque a configuração abaixo e veja as mesmas chaves mudarem. A terceira opção mantém `pt-BR` e sobrescreve duas mensagens.

### Exemplo

```tsx
<OrangeProvider
  locale="pt-BR"
  messages={{
    close: 'Fechar janela',
    resultsCount: '{count} produtos encontrados',
  }}
>
  <App />
</OrangeProvider>

// Dentro de qualquer componente:
const { locale, t } = useLocale()
t('close')                              // "Fechar janela"
t('pageOf', { page: 2, total: 10 })     // "Página 2 de 10"
t('resultsCount', { count: 3 })         // "3 produtos encontrados"
```

## Todas as chaves

Gerada a partir de `ptBR`, `enUS` e `esES`, exportados por `@orangesys/ui` — esta tabela está sempre em dia com o código. Trechos entre chaves, como {count}, são substituídos na interpolação.

## Interpolação

Use `{nome}` no texto e passe os valores no segundo argumento de `t()`. Variáveis ausentes ficam como estão, o que facilita achar erros. A mesma função está exportada como `interpolate()` para seus próprios textos.

`interpolate.ts`:

```ts
import { interpolate } from '@orangesys/ui'

interpolate('Página {page} de {total}', { page: 2, total: 10 })
// "${interpolate('Página {page} de {total}', { page: 2, total: 10 })}"

interpolate('Olá, {nome}! Você tem {n} pedidos.', { nome: 'Ana' })
// "${interpolate('Olá, {nome}! Você tem {n} pedidos.', { nome: 'Ana' })}"
```

## useLocale() nos seus componentes

Componentes da sua aplicação podem reaproveitar o dicionário. Prefira as chaves existentes a textos fixos: assim a tradução e as sobrescritas valem para tudo.

`Aviso.tsx`:

```tsx
import { Button, Icon, useLocale } from '@orangesys/ui'

export function Aviso({ children, onDismiss }: { children: React.ReactNode; onDismiss: () => void }) {
  const { t } = useLocale()
  return (
    <div role="status" className="aviso">
      <Icon name="info" label={t('info')} />
      <p>{children}</p>
      <Button variant="ghost" iconOnly aria-label={t('dismiss')} onClick={onDismiss}>
        <Icon name="close" />
      </Button>
    </div>
  )
}
```

> **Precisa de uma chave nova?** Ao contribuir com um componente, adicione a chave em `ptBR` e `enUS` (`packages/ui/src/providers/messages.ts`). O tipo `Messages` garante que nenhum idioma fique sem tradução.

## Adicionando um idioma

Para um idioma que o Orange não traz, crie um objeto `Messages` completo e passe-o em `messages`. Partir de `enUS` com spread garante que nenhuma chave fique faltando enquanto a tradução avança.

`fr-FR.ts`:

```tsx
import { enUS, OrangeProvider, type Messages } from '@orangesys/ui'

export const frFR: Messages = {
  ...enUS,
  close: 'Fermer',
  cancel: 'Annuler',
  loading: 'Chargement…',
  nextPage: 'Page suivante',
  pageOf: 'Page {page} sur {total}',
  // …
}

<OrangeProvider locale="fr-FR" messages={frFR}>
  <App />
</OrangeProvider>
```

## Datas, números e moedas

Formatação não é tradução: use as APIs `Intl` do navegador com o mesmo locale do provider. Elas cuidam de separadores, moeda, ordem de dia e mês, plurais e listas. A tabela abaixo é calculada ao vivo para 15/03/2026 14h30.

`Preco.tsx`:

```tsx
import { useLocale } from '@orangesys/ui'

export function Preco({ valor }: { valor: number }) {
  const { locale } = useLocale()
  const formato = new Intl.NumberFormat(locale, { style: 'currency', currency: 'BRL' })
  return <span className="preco">{formato.format(valor)}</span>
}
```

## Boas práticas

- Mantenha o `lang` do `<html>` igual ao locale; marque trechos em outro idioma com `lang` (3.1.2).
- Não concatene frases (`'Página ' + n + ' de ' + total`): a ordem das palavras muda entre idiomas. Use uma mensagem com variáveis.
- Deixe espaço: textos em português costumam ser 20–30% mais longos que em inglês. Evite larguras fixas em botões e abas.
- Para plurais, use `Intl.PluralRules` e escolha a mensagem pela categoria (`one`, `other`…).
- Textos do seu produto (títulos, rótulos de campo) chegam aos componentes por props, já traduzidos pela sua solução de i18n (react-intl, i18next, Lingui…).
